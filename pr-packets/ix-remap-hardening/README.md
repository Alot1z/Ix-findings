## Summary

Replaces the no-op `/__ix/remap` stub with a real endpoint that rebuilds the
code map by running `ix map .` in the visualizer's working directory. The
endpoint is hardened against CSRF and DNS-rebinding attacks, only accessible
from loopback. Also fixes the WSL bootstrap to correctly route through the
`curl|sh` installer path instead of the Windows PowerShell path.

## Motivation

The visualizer previously had no way to trigger a remap from the browser UI.
Users had to drop to a terminal and run `ix map .` manually. The `/__ix/remap`
route existed but was a stub that fell through to the SPA handler (returning
`index.html` with a 200, indistinguishable from any other unknown route).

## Implementation

### Real `/__ix/remap` Endpoint

- `POST /__ix/remap` spawns `node <cli-main> map .` with a 30-minute timeout
- Responds `{ "ok": true }` on success, `{ "ok": false, "error": "..." }` on failure
- The map runs in `process.cwd()` — the workspace the visualizer was launched from

### Loopback-Only Security Model

The endpoint shells out with the user's full privileges, so it is guarded by a
double loopback check:

1. **Host check** — rejects requests where `Host` header is not `localhost`,
   `127.0.0.1`, or `[::1]`
2. **Origin check** — rejects cross-site `Origin` headers (any non-loopback
   hostname), malformed origins (URL parse failure), and non-http/https
   protocols; accepts missing `Origin` (curl-style, same-origin fetch)

Both must pass for the request to proceed. Failure returns `403
{ "ok": false, "error": "forbidden: loopback only" }`.

### Design Decisions

- **Origin parsed with `new URL()`**, not a regex: the server code lives inside
  a template literal in `serverScript()`. Regex backslashes would be consumed
  every time the server is regenerated by `ix view start`. The URL API avoids
  this class of bug entirely.
- **IPv6 bracketed literals**: `[::1]:8080` is correctly parsed by stripping
  the port from the closing bracket position, not by splitting on `:`.
- **Response "close" for client-disconnect reaping**: `res.on("close", ...)`
  with a `writableEnded` check distinguishes normal completion from abnormal
  client disconnect, avoiding killing the map mid-flight on certain Node
  versions that fire request `close` on completion.
- **`IX_VIEW_MAP_MAIN`**: test seam to point the server at a stub CLI instead
  of the real installation, enabling integration tests without a full build.

### Server Binding

The generated server binds explicitly to `127.0.0.1` (was previously `PORT`
only, which defaults to `::` on some Node versions).

### Exported `serverScript()`

The `serverScript` function is now exported (from `view.ts`) so tests can
generate, inspect, and execute the inline server script directly.

### WSL Bootstrap Fix

`is_windows()` previously treated `WSL_DISTRO_NAME` as Windows, causing WSL
installs to take the PowerShell path. WSL is Linux (uname = Linux) and must
use the `curl|sh` path. Fixed by removing the WSL test from `is_windows()`.

### Dead `node_ok` Removal

Removed the `node_ok` variable that was set but never read.

## Security Model

### Guard Matrix

| Scenario | Origin | Host | Result |
|----------|--------|------|--------|
| Cross-site CSRF | `https://evil.example` | `127.0.0.1:PORT` | **403** |
| DNS rebinding | (any) | `attacker.example` | **403** |
| Malformed Origin | `not a url` | `127.0.0.1:PORT` | **403** |
| Non-loopback Origin | `http://10.0.0.5:8080` | `127.0.0.1:PORT` | **403** |
| Curl / no Origin | (absent) | `127.0.0.1:PORT` | **200** ✓ |
| Same-origin loopback | `http://localhost:PORT` | `127.0.0.1:PORT` | **200** ✓ |
| IPv6 loopback Host | (absent) | `[::1]:PORT` | **200** ✓ |
| GET (not POST) | — | — | SPA fallback (200, index.html) |

### What Is NOT Changed

- The server remains bound to `127.0.0.1` — never `0.0.0.0`
- The existing `/v1/*` proxy is untouched
- The SPA fallback behavior is preserved
- Existing view behavior (`ix view`) is unchanged
- No new dependencies added

## Known Limitations

1. The remap endpoint has no rate limiting beyond the one-at-a-time constraint
   from the single-threaded server and client-disconnect reaping. This is
   acceptable for a loopback-only endpoint that the user controls.
2. The map command timeout (30 minutes) is generous. Very large workspaces
   could approach this limit.
3. The endpoint does not stream progress — the client waits for completion or
   timeout.

## Reviewer Notes

- The `serverScript` function is exported for testing. If adding more inline
  server logic, consider extracting to a separate file.
- The `res.on("close", ...)` with `writableEnded` guard handles a Node.js
  behavior difference: in some versions, the `IncomingMessage` (request)
  `close` event fires on normal completion, which would kill the map
  mid-flight. Using the `ServerResponse` (response) `close` event with the
  `writableEnded` check avoids this.
- The URL API is preferred over regex for Origin parsing because the server
  code lives inside a template literal; see the implementation comment for
  details.
