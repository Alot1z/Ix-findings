# Ix — Issue #376 (Version-Series Mismatch, F-008)

## The bug (SOURCE — `upgrade.ts` + `release.yml`)

Two unrelated version series feed one `isNewer` comparison:

```
release.yml (PR #365):  compass/.version ← "$VERSION" (Ix series, e.g. 0.9.1)
upgrade.ts:             compassLatest   ← ix-compass-dist latest (dist series, e.g. 0.3.0)
                        compassCurrent  ← getInstalledCompassVersion() (.version)
                        isNewer(compassLatest, compassCurrent)
```

Today `isNewer("0.3.0","0.9.1")` → false → no upgrade → correct **by accident**.
The moment ix-compass-dist tags ≥ the running Ix version (v0.9.2 / v1.0.0),
`isNewer` flips true and `ix upgrade` replaces the correct bundled Compass
(which is built from main and therefore **newer**) with an older dist build —
the same v0.9.1 regression, via a different route.

## History

1. v0.9.0: no `.version` stamp → `getInstalledCompassVersion()` = "0.0.0" →
   silent downgrade to v0.2.0.
2. PR #365 (KageBinary): stamp with Ix version — "the Ix version is a monotonic
   stand-in" (correct at the time; acknowledged in the commit: the stamp being
   present is what matters).
3. PR #366 (KageBinary): Windows tar path pairing.
4. Issue #376 (KageBinary, 2026-08-10): recognizes the mismatch; proposes
   options.

## Fix options (from the issue; maintainer decision required)

| Option | Idea | Pros | Cons |
|---|---|---|---|
| A | stamp with the compass/dist version | simplest; same series | stamp is a fiction (main is newer than any dist tag) |
| B | stamp source commit; compare identity | correct by construction | changes upgrade semantics; install.sh stamps dist versions |
| C | two fields (Ix version + compass commit) | most robust | larger change; migration for existing installs |

## Recommended position (this investigation)

Option A is the simplest correct fix (no `upgrade.ts` change needed), but the
choice belongs to KageBinary (author of #365/#376). Packet:
`../pr-planning/ix-376.md`, `../pr-packets/ix-376-version-mismatch/README.md`.
Must be a separate PR from remap (S-013, D-009).
